# פריסה: מנות 4 ו־5 (הצטרפות לכיתה + לוח כיתה)

לא הורצה שום פקודה בייצור. כל השלבים כאן הם לביצוע על ידך, בסדר הזה.

## 1. גיבוי
Supabase → Database → Backups: ודאו שיש גיבוי עדכני. המיגרציה הראשונה יוצרת מפתח הצפנה ב־Vault; **אסור למחוק או להחליף אותו** (`hevanti_identity_key`), אחרת מספרי הזהות השמורים לא יפוענחו. הגיבוי של Supabase כולל את ה־Vault.

## 2. מיגרציות (SQL Editor, כל קובץ כשאילתה נפרדת)
1. `20261118000100_join_links_and_identity.sql` (דורש שמיגרציה `20261117000300` הורצה; בודקת Vault ו־pgcrypto ונעצרת אם חסרים)
2. `20261118000200_class_board.sql`

כל קובץ עטוף ב־begin/commit, ולכן כשל לא משנה כלום. אחרי ההרצה עדכנו את הטבלה ב־`supabase/migrations/README.md`.

## 3. הגדרות Supabase Auth (בדשבורד)
- Authentication → Providers → Email: אפשרו **Allow new users to sign up**.
- Authentication → URL Configuration: הוסיפו ל־Redirect URLs את `https://<הדומיין>/join/**`.
- החליטו אם לדרוש אימות אימייל (מומלץ להשאיר דלוק; ה־UI מטפל בשני המצבים).
- מומלץ להפעיל CAPTCHA (Authentication → Attack Protection) נגד הרשמות אוטומטיות.
- אין צורך לשנות Edge Functions. מנגנון ההזמנה הקיים (`invite-student`) לא השתנה.

## 4. פריסת הקוד
מיזוג/דחיפה של הקבצים מה־ZIP בדרך הרגילה שלכם (לא בוצע כאן).

## 5. הערות פרטיות
- מספר זהות: מוצפן (`pgp_sym_encrypt`), יש לו גם אינדקס HMAC לאי־כפילות, שמור בסכמה `private` ללא גישת API. רק מורה של התלמיד יכול לחשוף אותו דרך `reveal_student_id`, וכל חשיפה נרשמת. אין UI לחשיפה כרגע (ה־RPC קיים).
- קטינים: טופס ההרשמה כולל אישור תנאים והצהרה על ידיעת הורה לתלמיד מתחת ל־18. מומלץ לוודא מול היועץ המשפטי שהניסוח מתאים למדיניות הפרטיות שלכם.
- מחיקת תלמיד (`delete-student`): שורת הזהות נמחקת אוטומטית (CASCADE). `admin_student_footprint` עדיין לא מונה אותה.
- לוח הכיתה: תלמידים רואים זה את זה כשם פרטי + האות הראשונה של שם המשפחה; רק המורה רואה שמות מלאים.
